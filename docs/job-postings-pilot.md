# Additional Scout job corpus pilot — held from activation

This supplies public employer postings to PL, which retains customer criteria, ranking and outreach control. It is separate from PL go-live. Nothing schedules refreshes, creates applications, or activates providers automatically.

Apply additive migration `004_job_postings.sql` through the normal release process before activation. Only after separate release approval, set `SOURCEFOUNDRY_JOBS_ENABLED=1` and `SOURCEFOUNDRY_JOB_SOURCES` to a JSON array of operator-verified `smartrecruiters:company` or `workable:company` identifiers. Both reads and refreshes require the existing operator bearer token. Agent keys are denied. No customer identifier or private search criteria are accepted. No new credentials or dependencies are needed.

- `POST /v1/job-postings/refresh` with `{ "source": "workable:company" }`: returns schemaVersion, release, source, checkedAt, complete, count, error. Refreshes are serialized per source, bounded to 200 postings, 45 seconds and the existing safe-fetch 2 MiB response ceiling. No automatic retry.
- `GET /v1/job-postings?source=workable:company&limit=200`: returns `{ schemaVersion: 1, release, source, checkedAt, complete, jobs }`. Jobs contain id, url, title, company, location, description, publishedAt, firstSeenAt, lastSeenAt and status (`open` or `removed`). Descriptions may contain provider HTML: treat as untrusted text, never render without sanitation. Workable company is the configured account slug.

firstSeenAt survives updates and reappearance. publishedAt comes from the provider and never substitutes for firstSeenAt. lastSeenAt changes only when the posting was observed. Only a complete successful enumeration marks absent postings removed. Removed means absent from that employer board, not proof of fraud or a ghost job. Errors and partial results retain earlier records, report complete=false, and cannot provide the first verified snapshot. GET returns 503 until one complete snapshot exists. A bounded GET reports complete=false when records were omitted. A later failed refresh keeps the corpus readable but incomplete.

SmartRecruiters returns empty results for unknown company names; zero-result boards therefore remain unconfirmed in this pilot and cannot remove prior jobs. Boards above 200 jobs remain incomplete and need a separately scoped pagination extension before admission. Description enrichment is sequential and may exhaust the time budget for large boards. Workable's public widget gives a single snapshot; a valid empty jobs array is accepted as complete. Confirm company ownership and an initial nonempty response before allowlisting it. Country coverage follows the chosen employers, not a provider-wide India guarantee.

Before activation: validate migration and atomic refresh behavior against isolated PostgreSQL; verify current provider endpoints and account identities for selected India employers; run exact-candidate API auth/contract checks and PL disabled-mode regression checks. No migration, deployment, live refresh, scheduled job or rollout is authorized by this source change alone.
